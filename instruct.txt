1. PROBLEM STATEMENT & DOMAIN CONTEXT
================================================================================

1.1 Background & Institutional Context:
The Sashastra Seema Bal (SSB), under the Ministry of Home Affairs, is tasked with 
securing India's porous land borders (Indo-Nepal: 1,751 km and Indo-Bhutan: 699 km). 
These checkpoints experience immense daily transit volume involving diverse travel 
documents: Passports, Visas, Indian Voter ID Cards (EPIC), Nepali Citizenship 
Certificates (Nagrikta Praman Patra), Driving Licenses, and Border Transit Permits.

1.2 Operational Bottlenecks:
- Time Constraints: Checkpoint guards have only a few seconds per passenger, 
  leading to extreme friction during peak hours.
- Digital Forgery: Fraudsters use basic image editors to alter dates of birth, 
  names, and visa validity periods.
- Photo Splicing: Criminals physically or digitally paste new portrait photographs 
  onto valid identity documents.
- Analog Laundering: Tampered digital documents are printed and scanned as low-quality 
  images to strip file metadata, bypassing standard cyber forensics.
- Visual Blindspot: Manual inspection reads visual text but cannot verify embedded 
  cryptographic or algorithmic checksums (such as ICAO 9303 Modulo-10 check digits).

1.3 System Objective:
Develop an automated, edge-capable triage platform that processes document images 
and live traveler camera frames in under 2 seconds, extracting all fields, 
validating compliance standards, detecting digital/physical tampering, performing 
1:1 facial biometric matching, and outputting an explainable Border Threat Index (0–100%).

2. PRODUCT REQUIREMENTS DOCUMENT (PRD)
================================================================================

2.1 Target User Persona:
SSB Checkpoint Sub-Inspector / Border Security Guard operating a ruggedized terminal 
or laptop at a border outpost. Needs instant, high-contrast, traffic-light visual 
cues (GREEN: Clear, YELLOW: Review, RED: Detain) with clear bounding-box evidence.

2.2 Core In-Scope Feature Set (MVP):
- Multi-Format Ingestion: Accepts image uploads (JPG, PNG, PDF) from flatbed 
  scanners, mobile cameras, or connected USB webcams.
- Module 1 (OCR & MRZ Extraction): Extracts both the Visual Inspection Zone (VIZ) 
  and the 2-line/3-line Machine-Readable Zone (MRZ).
- Module 2 (Document Validation Engine): Executes ICAO Doc 9303 Modulo-10 checksum 
  checks, expiration validations, and VIZ-to-MRZ text parity matching.
- Module 3 (Core Forensic Tampering AI): Executes Error Level Analysis (ELA) to 
  detect compression variance from spliced photos or pasted text, and checks 
  metadata for editor signatures.
- Module 4 (Biometric 1:1 Facial Verification): Crops document portrait face and 
  computes Cosine similarity distance against a live webcam capture.
- Incident Dossier Output: Generates an explainable threat scorecard with visual 
  heatmaps and forensic flags for legal logging and immediate triage.

3.3 Algorithmic & Mathematical Specifications:

3.3.1 ICAO Doc 9303 Modulo-10 Checksum Algorithm (Module 2):
- Weighted multipliers cycle through: [7, 3, 1, 7, 3, 1, ...]
- Character values: '0'-'9' -> 0-9, 'A'-'Z' -> 10-35, '<' (filler) -> 0.
- Formula:
    Check_Digit = ( Sum( Character_Value[i] * Weight[i mod 3] ) ) mod 10
- Verification Rules:
    - Checksum 1: Document Number (Characters 0-9 of Line 2)
    - Checksum 2: Date of Birth in YYMMDD (Characters 13-19 of Line 2)
    - Checksum 3: Date of Expiry in YYMMDD (Characters 21-27 of Line 2)
    - Checksum 4: Composite / Overall Checksum

3.3.2 Error Level Analysis (ELA) Algorithm (Module 3):
- Re-compresses the input image at a fixed 90% JPEG quality level in memory.
- Calculates the absolute pixel difference between original and re-compressed arrays:
    ELA_Difference = | Image_Original - Image_Resaved |
- Scales extrema variance to an 8-bit scale (0-255) to generate a high-contrast heatmap.
- Computes mean difference intensity across the image. An anomaly is flagged if 
  localized pixel intensity clusters deviate significantly from background baseline.

3.3.3 Facial Embedding Distance Metric (Module 4):
- Detects bounding box for portrait on document and live frame.
- Computes facial feature embeddings (v1, v2) and measures Cosine Distance:
    Cosine_Distance = 1 - ( (v1 . v2) / ( ||v1|| * ||v2|| ) )
- Decision Thresholds:
    - Distance <= 0.35: Verified Match (Same Individual)
    - 0.35 < Distance <= 0.45: Warning / Secondary Review
    - Distance > 0.45: Tampering / Impersonation Alert

3.3.4 Composite Threat Scoring Engine:
- Calculates an integer score from 0 to 100 based on weighted violation penalties:
    Threat_Score = Min( 100, 
      (35 * Checksum_Failed) + 
      (30 * VIZ_MRZ_Mismatch) + 
      (35 * ELA_Tamper_Detected) + 
      (40 * Face_Mismatch) + 
      (20 * Metadata_Anomaly) + 
      (25 * Document_Expired)
    )
- Threat Levels:
    - GREEN (Threat Score < 30): Clear / Low Risk
    - YELLOW (30 <= Threat Score < 70): Review / Moderate Risk
    - RED (Threat Score >= 70): Detain / High Risk Tampering

3.4 API Interface Specification:
- Endpoint: POST /api/v1/screen
- Request Type: multipart/form-data
  - document: File (Required, binary image of ID/Passport)
  - live_photo: File (Optional, binary snapshot of traveler)
- Response Format: JSON
  - status: "success" | "error"
  - threat_level: "GREEN" | "YELLOW" | "RED"
  - composite_risk_score: Integer (0-100)
  - flags: List of string descriptions for all triggered anomalies
  - extracted_data: Object containing Name, Document Number, Nationality, DOB, 
    Expiry, Gender, and individual checksum boolean results
  - forensic_analysis: Object containing ELA tamper status, numeric score, and 
    Base64-encoded JPEG heatmap string
  - biometric_verification: Object containing match boolean, distance score, and 
    confidence metrics
